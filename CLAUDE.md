# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"Federal Monkey Patrol" (codename Kong): a 2004–2006 game by Dave Lawrence (code) and Sam Norman (art), GPL v2. You fly a biplane over a procedurally generated city shooting monkeys; `game.txt` holds the design notes and `todo.html` the author's TODO/refactoring ideas.

The main version is now a browser port (Vite + Three.js, TypeScript) deployed to GitHub Pages. The original C++ / OpenGL / SDL 1.2 code is in `legacy/` for history only (tag `v2006-native` has the pre-port tree): the port no longer tracks it, and the code shouldn't point back to it or keep C++ behaviour just for compatibility. Milestone 1 (issue #1) is a faithful recreation of what the 2006 build actually did: no new gameplay. Things that were switched off or never implemented in 2006 (Giant Claw meter, skip key, small monkeys, blondes) stay off until later milestones. Since milestone 1, the user has asked for some additions: a throttle (the plane had no forward velocity in 2006), a button to switch between follow and top-down flying, on-screen touch controls, more responsive controls with a chase camera, a procedurally textured 1920s–40s New York (midrise buildings, facades, street furniture, period street markings), top-down mode climbing clear of the roofs, a friendlier story (stacked dialogue, slower timing in `story.properties`, tap to advance, skip link, pause menu), an old-movie look (colour, but graded most of the way to black and white), billboard trees (now fixed crossed quads), level of detail for the city, a spinning propeller, collisions (the plane explodes on hitting a building or the street and comes back over the rooftops, blinking and briefly invulnerable; `lives` in `game.properties`, shown as Harlow's heads, then GAME OVER and status `LOST`; bullets throw sparks, bombs explode), kongs (King Kong-sized apes, `kong2.obj`, no animation: they walk the streets, sometimes climb a building to roar from its roof, and fall to the street after 5–10 hits, counting `MONKEY_DEATHS`; tuned in `kong.properties`, `<kongs>N</kongs>` in a mission's `<startconditions>` sets how many), a patrol area (a circle of `patrol_radius` round the start, in `game.properties`: the kongs keep inside it, a heading-up radar at the top right shows them and its edge, and flying out gives `turn_back_seconds`, with the clock stopped while heading back in, before losing a plane and being turned round to face the middle), a "Last updated" line on the menu (build time and commit, from `define` in `vite.config.ts`), a minimum speed (`min_speed`/`max_speed` in `game.properties` are the throttle's range; top-down mode never goes below it either), game modes picked on the title screen (each a `.game` file holding one mission: Clear the Area (`clear.xml`, a fixed number of kongs, won when `MONKEY_POPULATION` reaches 0), Monkey Mayhem (`mayhem.xml`, many weaker kongs respawning quickly, three minutes) and Free Patrol (`fly.game`); missions will later be slotted into the story; an outcome's message shows as a banner with how it went, and again on the menu), and top-down bullets that make that mode 2D (they fly level over the city, hit whatever their path crosses on the map at any height, and curve down onto it).

## Build & run

- `npm install`, then `npm run dev` (Vite dev server) or `npm run build` (type-checks, then builds the static site in `dist/`). `npm run typecheck` runs `tsc` alone; Vite itself only strips types, so the dev server runs code with type errors.
- TypeScript is strict (`tsconfig.json` for `src/`, `tsconfig.node.json` for `vite.config.ts`), `noEmit`, and local imports use the `.ts` extension. Enum-likes are `as const` objects with a type of the same name (`Status`, `Button`, `Stat`).
- The game fetches its original data files at runtime, with paths relative to the site root (the repo root): `data/`, and the `*.game` files at the root. The build copies them into `dist/` as-is (see `vite.config.ts`); they don't go through Vite's asset pipeline.
- `?game=<path>` picks the `.game` file (default: `default_game` in `data/etc/main.properties`). The page always starts at a menu, because browsers need a click before audio can play.
- Deploy: `.github/workflows/pages.yml` builds and deploys to Pages on every push to `main`.
- There are no tests beyond the type check. Check changes by running the game; a headless browser needs WebGL (e.g. Chromium with `--use-angle=swiftshader`).

## Architecture (`src/`)

- `main.ts`: menu (`GAMES`: game modes, the story, extras), the pause button/menu (Esc toggles it; the old instant quit is gone) and the story's "Skip to game" link (next mission, or `fly.game` if there is none), then the main loop: `inputmanager.update(); display.beginFrame(); game.play(display, msecs, input)` until status is `QUIT`.
- `core/`: `display.ts` (renderer, 4:3 letterboxed view, offscreen targets; asks for the high-performance GPU and logs the renderer, and the menu warns when the browser is using a software rasteriser), `filmlook.ts` (the old-movie grade: appended to three's `dithering_fragment` chunk so every built-in 3D material gets it after fog; `filmColor()` grades 2D colours that must match, like the FogPlane sky), `draw2d.ts` (immediate-mode 2D batcher in the original's ortho space of 1.0 x 0.75, plus `Drawable2D`/`Quad`/`Image`/`Container2D`/`Text2D` with the original bitmap font metrics, `WordList2D`), `assets.ts` (text, textures, OBJ models, Web Audio, `playBang()`: a synthesised explosion), `settings.ts` (`data/etc/*.properties`), `input.ts` (keyboard/gamepad into an `Input` struct with buttons, axis and a persistent `throttle`; `InputFilter`/`MenuFilter`), `touch.ts` (on-screen stick/throttle/fire/mode/quit, another InputManager device; shown by `main.ts` only while a mission is flying), `PointerTap` in `input.ts` turns canvas taps into `Button.NEXT`; `mtrand.ts` (Mersenne Twister, so a seed always gives the same city).
- `game/`: `component.ts` (`GameComponent` with status `PLAYING`/`NEXT`/`LOST`/`QUIT`; async `load()`, `play()` draws nothing until loaded), `manager.ts` (`GameManager` + `.game` file reader), `stage.ts` (the HTML stage over the 4:3 view: components with `isDom` show a DOM layer each frame with `stage.show()`, unshown layers are dropped at `endFrame()`; `withEffect()` lets transitions fade/clip them), `simple.ts` (Blank and Picture as HTML layers, SoundTrack), `storyteller.ts` (`.shot` cutscenes as an HTML layer: picture plus a dialogue box where consecutive lines stack while they fit, speakers named, a tap/click/Space/Enter moves on), `transition.ts` (fade, spin, starwipe, `hwipe`/`vwipe`/`NNwipe`; with an HTML side the mask is a CSS clip-path, or an inverted mask on the HTML prev over a WebGL mission; between two WebGL components the next is rendered offscreen and drawn through the mask).
- `mission/`: `mission.ts` (Mission + MissionBuilder from `data/missions/*.xml` via `DOMParser`; `<startconditions>` can hold `<kongs respawn_msecs="N|never" health_min="N" health_max="N">count</kongs>` and `<patrolradius>`; an outcome calls `finish()`, which shows its message (`{stat_name}` is replaced by the stat) for a few seconds with the plane `charmed`, then takes the status; `lastResult` is what the menu shows), `outcomes.ts` (Scenario/Condition/Result, Constraints), `stats.ts` (global `gamestats`), `world.ts` (World scene, Entity/Plane/Projectile, FollowPlaneFilter and TopDownPlaneFilter, Player with its two modes (the propeller is split off the plane model by connected parts ahead of the nose and spun with the throttle); stick input sets smoothed turn rates, yaw is about world up and banking is visual only; CameraMan with a chase camera that blends into the top-down view; `World.update` sweeps each entity with a `radius` from its old to its new position through `CityGrid.sweep()` and against `shootable` entities' `intersect()`, and calls its `hit()` with the target, if any (bullets call the target's `struck()`; bombs also `World.blast()`); top-down bullets are `flat` (no city collisions; `Projectile.update` tests their ground track against shootable entities' `aim()` and curves down to the first ahead); the plane crashes into kongs as into buildings; top-down mode climbs to `CityGrid.maxHeightNear()` plus a clearance), `city.ts` (`CityGrid`: 8x8 patches of 8x8 blocks kept centred on the camera, generated with `MTRand(42)` and merged into per-patch meshes; new patches are generated one per frame as the plane flies. The 2006 generator still sets every lot's position and size; the styling comes from a separate RNG hashed from each building's position, so the MTRand sequence is unchanged: each lot is split into walk-ups, lofts and taller buildings with storefronts or lobbies, cornices, bulkheads and water tanks; skyscrapers get setbacks and 1910s–30s crowns; lamp posts and hydrants are instanced per quarter-patch; all trees (park and street) are instanced cross trees (two quads at right angles, fixed in the world at a random turn); cornices get no overhang on sides shared with a neighbour and never more than half the 2006 `SPACING`, so neighbouring ledges don't overlap and z-fight. Walls are one mesh per patch textured from `facades.ts`. Level of detail: each patch always has a lite version of its buildings (walls straight to the street, no trim, a point for each metal crown; built by the same code with the detail sent to a `NULL` builder so the random numbers match); the full version (storefronts, lobbies, cornices, water tanks, crowns, street furniture) is built lazily, one patch per frame, within `NEAR_DISTANCE` and dropped again beyond it plus `NEAR_KEEP`. Lamps switch to a low-poly post past `LAMP_DISTANCE`; furniture goes past `FURNITURE_DISTANCE`, trees past `TREE_DISTANCE`, patches past the fog. Collisions: the lite builders note boxes through `Builder.solid()` (walls, blocks, a pyramid as three narrowing boxes), kept per block; `sweep()` slab-tests a segment against them and the street), `kongs.ts` (`Kong`: a task list (walk, step, turn, climb, wait, wall) planned at each street crossing (streets run along multiples of `BLOCKSIZE`); climbs pick a ground-level box from `CityGrid.blockBoxes()` on a corner of the crossing whose street face is clear to the top; a capsule for hits; shot down, it falls outward off a wall or topples away from the shot, lies there, then sinks away. `KongTroop` keeps `count` of them in the patrol area, spawning at crossings away from the plane and each other and respawning after deaths; near the area's edge a kong only takes streets back in), `effects.ts` (particles: one `THREE.Points` per layer (sparks, fire, smoke) with per-particle size and RGBA in a ShaderMaterial that does its own fog and gets the film grade; `sparks()`, `explosion()`, `furHit()`, `dust()`), `facades.ts` (procedural canvas textures: a texture array of facade kinds, 4x4 window bays per tile, mapped so each face is a whole number of bays and floors line up; plus the street tile, painted to the 2006 `city_block_base.png` layout), `hud.ts` (FogPlane, CountDownTimer, ClawAlert, LivesDisplay, Radar, TurnBack, FPS readout, LoadBar).
- `tuner.ts`: lil-gui built from `data/etc/toggles.xml`; Insert or backquote toggles it and pauses the current component.

Conventions: textures use `flipY = false` so texcoord v=0 is the top of the image (the models' and 2D drawing's texcoords assume it), and `Picture`/`Blank` default to status `NEXT`, so they show for one frame unless a transition is drawing them. `play()` gets `input = null` when a component is drawn frozen (paused, or by a transition). Some 2006 quirks are still in place and commented (e.g. the constraint keys in `mission.ts`); they can be fixed now rather than preserved.

## Game data (`data/`)

- `.game` files: one component per line: `storyteller <file.shot>`, `mission <file.xml>`, `blank <hexcolor>`, `picture <img> [msecs] [hexcolor]`, `music <file>`, and `transition <type> <msecs>`, which links the previous and next components. `#` comments.
- `etc/`: config (`display`, `story`, `physics`, `game`, `main`, `tuner`, `city`, `kong` properties; `toggles.xml`; `projectiles/`), `missions/` XML, `story/` `.shot` scripts and images, `models/` (`.obj`), `images/`, `sound/`.
